_무작위 SSH 로그인 시도 로그_

## 이게 뭐야?

열심히 구글링을 해보니 이것은 매우 일반적인 상황으로 많은 봇넷들이 이런식의 무차별 대입 공격(Brute Force Attack)을 하는 것으로 파악됐습니다.

> 이러한 공격은 일반적으로 자동화된 봇이 다양한 사용자 이름과 비밀번호 조합을 시도하여 시스템에 무단으로 접근하려는 시도입니다.
{: .prompt-warning }

**공격 패턴 분석:**
- `Invalid user {username}`: 존재하지 않는 사용자명으로 로그인 시도
- `from {ip address}`: 다양한 IP 주소에서 시도 (봇넷)
- `port {port}`: 여러 포트를 통한 접근 시도
- `preauth`: 인증 전 단계에서 차단됨

## 해결 방법

무차별 대입 공격에 대한 일반적인 방어 방법은 다음과 같습니다.

### 1. 강력한 비밀번호 설정

무차별 대입으로도 찾을 수 없는 엄청 복잡한 password 설정

**장점:**
- 구현이 간단함

**단점:**
- 여전히 공격 시도는 계속됨
- 사람이 기억하기 어려운 비밀번호

### 2. Root SSH 로그인 비활성화

Root에 대한 SSH login 비활성화
```bash
# /etc/ssh/sshd_config
PermitRootLogin no
```

**장점:**
- Root 계정 직접 공격 차단

**단점:**
- 다른 사용자 계정은 여전히 타겟

### 3. 비밀번호 인증 비활성화

Password 기반 인증 비활성화 (키 기반 인증만 허용)
```bash
# /etc/ssh/sshd_config
PasswordAuthentication no
PubkeyAuthentication yes
```

**장점:**
- 무차별 대입 공격 원천 차단

**단점:**
- 키 관리 필요

### 4. SSH 포트 변경

22번이 아닌 다른 포트에서 SSH 서버 실행
```bash
# /etc/ssh/sshd_config
Port 2222
```

**장점:**
- 자동화된 봇 공격 상당수 회피

**단점:**
- 보안상 "obscurity"에 의존 (근본적 해결 아님)

### 5. Fail2ban 사용

[Fail2ban](https://github.com/fail2ban/fail2ban)을 사용하여 공격자의 IP를 자동으로 차단
```bash
# fail2ban 설치
yum install fail2ban -y

# 설정 예시
[sshd]
enabled = true
port = ssh
logpath = /var/log/secure
maxretry = 3
bantime = 3600
```

**장점:**
- 자동화된 차단
- 반복 공격 방지

**단점:**
- 설정 및 관리 필요
- 정상 사용자도 실수로 차단될 수 있음

### 6. 화이트리스트 기반 접근 제어 (채택)

화이트리스트에서만 SSH 허용
```bash
# /etc/hosts.allow
sshd: 192.168.1.0/24
sshd: 10.0.0.0/8

# /etc/hosts.deny
sshd: ALL
```

**또는 방화벽 규칙:**
```bash
# iptables 예시
iptables -A INPUT -p tcp --dport 22 -s 192.168.1.0/24 -j ACCEPT
iptables -A INPUT -p tcp --dport 22 -j DROP

# firewalld 예시
firewall-cmd --permanent --zone=trusted --add-source=192.168.1.0/24
firewall-cmd --permanent --zone=public --remove-service=ssh
firewall-cmd --reload
```

**장점:**
- 확실한 접근 제어
- 불필요한 공격 시도 원천 차단

**단점:**
- 외부에서 접근 불가 (VPN 필요)
- IP 변경 시 업데이트 필요

## 선택한 해결 방법

이렇듯 많은 방법들이 있지만, 사내 상황에 맞는 **화이트리스트만 SSH를 허용하는 방법**을 채택했습니다.

### 선택 이유

1. **현재 인증 방식**: 이미 public/private key 방식으로 로그인하고 있어 비밀번호 공격이 효과 없음
2. **접근 패턴**: 모든 접속이 사내 네트워크 또는 VPN을 통해 이루어짐
3. **운영 안정성**: 다른 방법들은 예상치 못한 이슈를 발생시킬 수 있음
4. **명확한 보안**: 허용된 IP만 접근 가능하여 공격 시도 자체를 차단

### 구현 결과

**Before:**
```
Nov 20 15:23:41 server sshd[12345]: Invalid user admin from 185.xxx.xxx.xxx port 54321
Nov 20 15:23:42 server sshd[12346]: Invalid user root from 192.xxx.xxx.xxx port 12345
Nov 20 15:23:43 server sshd[12347]: Invalid user test from 172.xxx.xxx.xxx port 23456
```

**After:**
```
(화이트리스트 외 IP의 접근 시도는 방화벽 레벨에서 차단되어 로그에도 남지 않음)
```

> 화이트리스트 방식을 사용하면 로그에 공격 시도조차 기록되지 않아 서버 리소스도 절약됩니다.
{: .prompt-tip }

## 정리

SSH 무차별 대입 공격 대응 방법 비교:

| 방법 | 효과 | 구현 난이도 | 부작용 |
|:---|:---:|:---:|:---|
| **강력한 비밀번호** | 낮음 | 쉬움 | 공격 시도 계속 발생 |
| **Root 로그인 차단** | 중간 | 쉬움 | 다른 계정은 여전히 타겟 |
| **비밀번호 인증 비활성화** | 높음 | 중간 | 키 관리 필요 |
| **포트 변경** | 중간 | 쉬움 | 근본적 해결 아님 |
| **Fail2ban** | 높음 | 중간 | 설정 관리 필요 |
| **화이트리스트** | 매우 높음 | 중간 | VPN 필요, IP 관리 필요 |

### 권장 조합

가장 안전한 방법은 **여러 방어 계층을 조합**하는 것입니다:

1. **필수**: 비밀번호 인증 비활성화 + 키 기반 인증
2. **필수**: Root 로그인 차단
3. **선택**: 화이트리스트 (접근 패턴이 명확한 경우)
4. **선택**: Fail2ban (화이트리스트 사용 불가 시)
5. **선택**: 비표준 포트 사용 (추가 보안 계층)

### 모니터링

보안 설정 후에도 지속적인 모니터링이 중요합니다:
```bash
# SSH 로그인 시도 확인
tail -f /var/log/secure | grep sshd

# 실패한 로그인 시도 통계
grep "Failed password" /var/log/secure | wc -l

# 공격 IP 목록
grep "Failed password" /var/log/secure | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr
```

### 교훈

처음에 로그를 봤을 땐 혹시나 서버가 털렸나 싶어서 등에 식은땀이 났지만 큰 이슈 없이 해결할 수 있어서 다행이었습니다.

**핵심 포인트:**
- SSH 공격은 매우 흔한 일이며, 모든 공개 서버가 타겟
- 여러 보안 계층을 조합하여 방어
- 정기적인 로그 모니터링으로 이상 징후 조기 발견
- 사내 환경에 맞는 적절한 보안 정책 선택

> 보안은 한 번 설정하고 끝나는 것이 아니라 지속적인 관리가 필요합니다.
