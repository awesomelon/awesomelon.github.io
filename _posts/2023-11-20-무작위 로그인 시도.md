로그를 확인하던 중 심상치 않은 기록을 발견했어요.

![2023-11-20-image1](2023-11-20-image1.png)
_무작위 SSH 로그인 시도 로그_

여러 사용자 이름으로 반복되는 로그인 실패는 자동화된 무차별 대입 공격(Brute Force Attack)을 의심하게 했어요. 다만 실패 로그만으로 공격 주체가 봇넷인지, 어떤 비밀번호를 시도했는지까지 알 수는 없습니다.

---

## 해결 방법들

### 1. 강력한 비밀번호 설정

충분히 길고 다른 서비스에서 재사용하지 않는 비밀번호를 설정해 추측을 어렵게 합니다. 비밀번호를 강화해도 공격 시도 자체는 계속됩니다.

### 2. Root SSH 로그인 비활성화

```bash
# /etc/ssh/sshd_config
PermitRootLogin no
```

### 3. 비밀번호 인증 비활성화

키 기반 인증만 허용합니다.

```bash
# /etc/ssh/sshd_config
PasswordAuthentication no
KbdInteractiveAuthentication no
PubkeyAuthentication yes
AuthenticationMethods publickey
```

기존 접속을 유지한 상태에서 키 로그인이 되는지 먼저 확인하고, `sshd -t`로 설정을 검사한 뒤 배포판에 맞는 방법으로 sshd 설정을 다시 로드합니다. 구형 버전에서는 `KbdInteractiveAuthentication` 대신 `ChallengeResponseAuthentication` 이름을 사용할 수 있어요.

### 4. SSH 포트 변경

```bash
# /etc/ssh/sshd_config
Port 2222
```

자동화된 봇 공격 상당수를 회피할 수 있지만 근본적 해결은 아니에요.

### 5. Fail2ban 사용

```bash
yum install fail2ban -y
```

CentOS 계열의 파일 로그 환경을 가정한 설정입니다. 저장소에 패키지가 있어야 하며, 설치 후 아래 내용을 저장하고 Fail2ban 서비스를 활성화해야 합니다. SSH 포트를 바꿨다면 `port`도 실제 포트로 바꿔주세요.

```ini
# /etc/fail2ban/jail.local
[sshd]
enabled = true
port = ssh
logpath = /var/log/secure
maxretry = 3
bantime = 3600
```

### 6. 화이트리스트 기반 접근 제어 (채택)

클라우드 보안 그룹이나 서버 방화벽에서 사내·VPN 주소만 허용합니다. `/etc/hosts.allow`와 `/etc/hosts.deny`는 TCP Wrappers 지원 빌드에서만 유효하며, OpenSSH 본류는 6.7에서 해당 지원을 제거했으므로 이 파일만으로 차단된다고 가정하면 안 됩니다.

아래는 iptables의 IPv4 규칙 예시입니다. 기존 INPUT 규칙에서 먼저 허용되거나 차단되지 않는 위치에 배치해야 하고, 주소는 서버가 실제로 보는 사내·VPN 출발지 주소로 바꿔야 합니다. IPv6로 SSH를 열었다면 그쪽에도 별도 제한이 필요해요.

```bash
iptables -A INPUT -p tcp --dport 22 -s 192.168.1.0/24 -j ACCEPT
iptables -A INPUT -p tcp --dport 22 -s 10.0.0.0/8 -j ACCEPT
iptables -A INPUT -p tcp --dport 22 -j DROP
```

## 선택한 해결 방법

사내 상황에 맞게 허용 목록에 있는 주소에서만 SSH에 접근하는 방법을 채택했습니다.

**선택 이유**
- 이미 키 기반 인증을 사용하고 있어 접속 경로 제한을 더하는 것이 적합함. 단, 키를 사용한다는 사실만으로 비밀번호 인증이 꺼진 것은 아니므로 설정 확인 필요
- 모든 접속이 사내 네트워크 또는 VPN을 통해 이루어짐
- 허용된 IP만 접근 가능하여 공격 시도 자체를 차단

방화벽에서 차단된 요청은 sshd까지 도달하지 않으므로 SSH 인증 로그와 처리 부하를 줄일 수 있습니다. 차단 기록이 남는지는 방화벽의 로깅 설정에 따라 달라져요.

---

## 같이 적용하면 좋은 것들

비밀번호 인증 비활성화 + 키 기반 인증, Root 로그인 차단은 기본으로 해두는 게 좋아요. 여기에 상황에 따라 화이트리스트, Fail2ban, 비표준 포트 변경 등을 조합하면 됩니다.

**모니터링:**

```bash
# SSH 로그인 시도 확인
tail -f /var/log/secure | grep sshd

# 실패한 로그인 시도 통계
grep "Failed password" /var/log/secure | wc -l

# 공격 IP 목록
grep "Failed password" /var/log/secure | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr
```

처음에 로그를 봤을 땐 혹시나 서버가 털렸나 싶어서 등에 식은땀이 났지만 큰 이슈 없이 해결할 수 있어서 다행이었습니다.
