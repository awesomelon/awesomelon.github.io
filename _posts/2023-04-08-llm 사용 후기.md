LLM을 직접 띄워보니, **대답을 잘하는 모델과 제품에 넣기 쉬운 모델은 같은 기준으로 고를 수 없었다.** 2023년 4월에는 LLaMA·Alpaca·Vicuna를 실행해 보고 GPT-3.5 API와 비교했다.

이 글은 당시 사용 기록에 모델 원리와 비교할 때 주의할 점을 덧붙인 글이다.

> 모델명, 가격, 라이선스와 실행 환경 기록은 2023년 4월 사용 당시 기준이다.
{: .prompt-info }

## LLM은 무엇을 학습할까?

이 글에서 다루는 GPT 계열 모델은 앞에 주어진 토큰을 바탕으로 다음 토큰의 확률을 학습한다. 토큰은 단어 전체일 수도, 단어의 일부일 수도 있다. 이 과정을 많은 텍스트에 반복하면서 문장 구조, 표현 방식, 지식에 관한 패턴을 학습한다.

다만 **자연스러운 다음 문장을 만드는 능력이 사실 확인을 대신하지는 않는다.** 질문에 맞는 문체로 유창하게 답하더라도, 근거가 없는 내용을 만들어낼 수 있다. 모델을 평가할 때는 문장의 완성도와 내용의 정확도를 따로 봐야 한다.

### Transformer가 바꾼 것

기존 RNN은 시퀀스를 순서대로 처리한다. [Transformer 원 논문](https://arxiv.org/abs/1706.03762)은 어텐션을 이용해 토큰 사이의 관계를 계산하고 학습할 때 여러 위치의 계산을 병렬화하기 쉬운 구조를 제안했다. 원 논문은 인코더와 디코더를 함께 쓰지만, GPT는 디코더 계열 구조로 다음 토큰을 차례로 예측해 문장을 만든다.

대화 품질 향상에는 구조뿐 아니라 데이터와 모델 규모의 확대, 지시를 따르는 예제로 학습하는 instruction tuning, 사람의 피드백을 반영하는 학습도 기여했다([ChatGPT의 학습 방식](https://openai.com/index/chatgpt/)). 그래서 기본 언어 모델과 대화용으로 조정한 모델을 같은 프롬프트로 비교하면 모델 크기 외의 차이도 함께 걸린다.

## 당시 비교한 모델의 관계

| 모델 | 출발점과 목적 | 결과를 읽을 때의 주의점 |
|:---|:---|:---|
| LLaMA 1세대 | Meta가 학습한 기본 언어 모델. 7B·13B·33B·65B | GPT-3를 파인튜닝한 모델이 아님. 대화용 조정 여부를 구분해야 함 |
| Alpaca 7B | LLaMA 7B에 지시 수행 예제를 추가 학습 | 제한된 평가 결과를 모든 작업의 동등한 성능으로 확대하면 안 됨 |
| Vicuna 13B | LLaMA에 대화 데이터를 추가 학습 | 초기 GPT-4 평가와 실제 제품 요구의 차이를 고려해야 함 |
| GPT-3.5-turbo | OpenAI가 API로 제공한 대화 모델 | 모델을 직접 운영하는 비용과 API 이용 비용은 비교 단위가 다름 |

[LLaMA 원 논문](https://arxiv.org/abs/2302.13971)은 7B부터 65B까지의 모델을 공개했다. 파라미터 수가 작다고 무조건 모든 작업에서 성능이 떨어지는 것은 아니며, 학습 데이터와 학습량, 평가 과제가 함께 영향을 준다.

![LLaMA 1세대 모델 비교 자료](2023-04-08-image1.png)
_LLaMA 모델 비교 자료_

Alpaca는 `text-davinci-003`으로 만든 약 5만 2천 개의 지시 수행 예제로 LLaMA 7B를 조정한 모델이다. [Stanford의 공개 글과 평가 한계](https://crfm.stanford.edu/2023/03/13/alpaca.html)의 예비 평가에서는 비슷한 수준을 보였지만 모든 질문에서 고르게 답한 것은 아니었고, 당시 공개본은 비상업적 연구용이었다.

![Alpaca 예비 평가 비교](2023-04-08-image2.png)
_Alpaca 예비 평가 비교 결과_

Vicuna의 “ChatGPT 품질의 90% 이상”이라는 표현도 분모를 함께 봐야 한다. [Vicuna 공개 평가와 한계](https://lmsys.org/blog/2023-03-30-vicuna/)는 연구진이 고른 80개 질문에 대해 GPT-4가 응답을 비교한 예비 평가였지, 실제 업무나 모든 언어에서 90% 정확도를 낸다는 뜻은 아니었다. 초기 LLaMA 기반 Vicuna 역시 비상업적 연구용이었다.

## 직접 사용한 환경과 느낌

환경은 CPU 80-core, RAM 320GB, T4 GPU 4개, Python 3.10이었다. 아래 숫자는 당시 실행하면서 메모해 둔 메모리 사용량인데, 체크포인트 형식이나 양자화, CPU offload, 문맥 길이 설정을 세세히 기록해 두지는 않아 최소 사양 기준으로 삼기는 어렵다.

| 모델 | 메모한 용량 | 사용하면서 느낀 점 |
|:---|:---|:---|
| LLaMA 7B·Alpaca 7B | 디스크 약 30GB, GPU 메모리 약 4GB 기록 | 비교적 부담 없이 실험했지만 한국어 글쓰기·코드 생성은 원하는 수준에 못 미쳤음 |
| Vicuna 13B | 디스크 약 40GB, GPU 메모리 약 28GB 또는 CPU 메모리 약 60GB 기록 | 앞의 두 모델보다 대화와 한국어 이해가 나았고 생산성 작업도 더 쓸 만했음 |
| GPT-3.5-turbo | 외부 API 사용 | 모델 서버를 구축하지 않아도 돼 연동이 가장 편했음 |

예를 들어 7B 파라미터를 각각 2바이트로 저장하면 **가중치만 약 14GB**다. 여기에 연산 중간값과 KV cache 같은 메모리가 추가된다.

따라서 위의 “GPU 4GB”를 비양자화 모델 전체가 그 메모리에 올라간다는 뜻으로 보기는 어렵다. 디스크 파일 크기와 실제 GPU 점유량, 전체 RAM 사용량은 따로 봐야 한다.

당시 살펴본 LLaMA·Alpaca 실행 구현은 내가 쓴 실행 도구가 REST API까지 묶어 주지 않아 별도 서버 코드를 붙여야 했다. Vicuna는 답변 품질이 상대적으로 나았지만 가끔 장황하게 이어지는 응답도 있었다.

![Vicuna가 장황하게 답변한 당시 화면](2023-04-08-image4.png)
_2023년 사용 중 기록한 Vicuna 응답 예시_

[2023년 API 출시 발표](https://openai.com/index/introducing-chatgpt-and-whisper-apis/) 당시 GPT-3.5-turbo 가격은 1,000토큰당 $0.002였다.

## 제품에 넣을 때는 무엇을 더 확인해야 할까?

그때는 답변이 얼마나 그럴듯한지에 먼저 눈이 갔다. 실제 제품에 들어갈 모델을 고른다면 아래처럼 **같은 업무와 같은 성공 조건**을 두고 비교하는 편이 낫다.

| 확인할 것 | 비교 방법 | 실패했을 때 드는 비용 |
|:---|:---|:---|
| 업무 정확도 | 실제 입력과 기대 결과를 정하고 누락·오답을 따로 기록 | 사람이 고치는 시간, 잘못된 후속 처리 |
| 한국어 지시 준수 | 같은 정보로 한국어·영어 지시를 주고 형식과 의미를 비교 | 번역·후처리의 복잡도 |
| 반복 사용의 안정성 | 동일 과제를 여러 번 실행하고 실패 유형을 기록 | 재시도 비용, 사용자의 불신 |
| 응답 지연 | 첫 응답까지의 시간과 전체 완료 시간을 구분 | 사용자가 기다리거나 이탈하는 시간 |
| 운영 부담 | 동시 요청, 요청 실패, 대화 이력 관리까지 포함 | GPU 운영 또는 API·저장 비용 |

“이전 대화를 기억하게 만들기”도 모델의 답변 능력과는 별개 문제다. [당시 API의 메시지 인터페이스 설명](https://openai.com/index/introducing-chatgpt-and-whisper-apis/)대로 Chat Completions 방식에서는 애플리케이션이 이전 메시지를 다음 요청에 직접 실어 보내야 했다. 이력을 무한히 넣을 수 없으므로 무엇을 남길지 정해야 하고, 이 선택이 곧 비용과 답변 품질로 이어진다.

당시 내 결론은 **빠르게 연동해보는 데에는 GPT-3.5 API가 편했고, 직접 모델을 실행하며 가능성을 살펴보는 데에는 Vicuna가 인상적이었다**는 것이다.

결국 모델 이름이나 공개 점수표보다, 내가 맡기려는 작업에서 허용할 수 없는 실패가 무엇인지 먼저 정하는 편이 훨씬 쓸모 있는 출발점이다.
