LLM은 대규모 데이터 셋을 학습해서 자연어 처리(NLP) 성능을 높이는 인공지능 모델이에요. LLM은 텍스트 생성, 요약, 기계 번역, 감정 분석 등에서 뛰어난 성능을 보여줍니다.

---

## 대화형 인공지능의 성능이 높아진 배경

대화 시스템에는 사람이 규칙을 작성하는 규칙 기반(Rule-based) 접근법과, 데이터로 학습하는 RNN/LSTM 같은 순차적 모델 등이 사용되어 왔습니다.

규칙 기반 시스템은 "if-then" 조건문으로 구현돼요. 간단한 대화는 잘 처리하지만 복잡한 상황에선 한계가 있죠.

RNN은 순차 데이터 처리용으로 설계된 신경망이에요. 하지만 장기 의존성(Long-term dependencies) 문제가 있어요. 시퀀스에서 멀리 떨어진 정보를 기억하기 어렵거든요.

### Transformer와 어텐션 메커니즘의 등장

Vaswani et al.이 2017년 "Attention Is All You Need" 논문에서 제안한 아키텍처예요.

Transformer는 RNN과 달리 학습 시 토큰 위치별 계산을 병렬화하기 쉬워요. 원 논문의 구조는 인코더와 디코더로 구성되지만, GPT처럼 디코더만 사용하는 모델도 있습니다. 자동회귀 방식의 텍스트 생성은 다음 토큰을 순차적으로 생성하므로 문장 전체가 한 번에 나오는 것은 아닙니다.

대화 성능 향상에는 이 구조뿐 아니라 학습 데이터와 모델 규모의 확대, 지시 따르기 학습과 사람의 피드백을 활용한 학습 등도 기여했습니다.

어텐션 메커니즘은 Transformer가 문장 처리 시 어떤 부분에 집중할지 결정하는 기술이에요. 각 단어의 관련 정보를 가중치로 표현하고 이를 바탕으로 모델이 중요한 정보에 집중하게 해줍니다.

## 대화형 인공지능 예시

### ChatGPT (GPT-3.5)

GPT(Generative Pre-trained Transformer)는 OpenAI의 언어 모델 계열입니다. 이 글에서 사용한 ChatGPT는 GPT-3.5 계열 모델을 기반으로 합니다. 1750억 개는 GPT-3의 가장 큰 모델에 공개된 파라미터 수이며, 이를 GPT-3.5의 수치로 그대로 사용할 수는 없습니다.

### LLaMA

[LLaMA](https://github.com/facebookresearch/llama)는 Meta에서 학습한 Transformer 기반 언어 모델 계열로, GPT-3를 파인튜닝한 모델은 아닙니다. 여기서는 2023년 2월 공개된 1세대의 7B, 13B, 33B, 65B 모델을 다룹니다.

가장 큰 65B 모델도 GPT-3 175B보다 작으며, LLaMA는 모델 크기에 따라 1조~1.4조 토큰으로 학습했습니다. 학습 데이터는 영어 중심이고 한국어 성능을 보장하는 모델은 아니지만, 한국어를 전혀 처리할 수 없다고 단정할 수는 없습니다.

![2023-04-08-image1](2023-04-08-image1.png)
_LLaMA 모델 구조_

### Alpaca

[Alpaca](https://github.com/tatsu-lab/stanford_alpaca)는 Stanford에서 공개한 연구 프로젝트입니다. LLaMA를 베이스로 파인튜닝한 모델입니다.

Alpaca 7B는 연구진의 제한된 지시 수행 평가에서 text-davinci-003과 비슷한 결과를 보였습니다. 이를 모든 작업에서 동등한 성능이라고 해석해서는 안 됩니다. text-davinci-003의 파라미터 수도 이 비교에서 확정된 값으로 다루지 않습니다.

당시 공개된 Alpaca는 연구용이며 상업적 사용을 허용하지 않았습니다. 당시 LLaMA 라이선스가 non-commercial이고 OpenAI의 text-davinci-003에서 얻어낸 데이터를 활용했기 때문입니다.

![2023-04-08-image2](2023-04-08-image2.png)
_Alpaca 성능 비교_

### Vicuna

[Vicuna](https://vicuna.lmsys.org) 또한 LLaMA를 기반으로 파인튜닝한 모델입니다.

공개 당시 연구진의 GPT-4 기반 평가에서는 Vicuna-13B가 LLaMA와 Alpaca보다 좋은 결과를 보였고, ChatGPT와 Google Bard 대비 90% 이상 수준의 응답 품질을 보였다고 보고했습니다. 다만 80개 질문을 이용한 예비 평가이며, 연구진도 평가 방식의 한계를 밝혔습니다. 모든 작업에서 성능이 90%라는 뜻은 아닙니다. 이 글에서 다룬 초기 LLaMA 기반 모델은 비상업적 연구용입니다.

## 각 모델 사용 후기

아래는 2023년 4월 당시 사용한 구성에서의 후기입니다. 디스크와 메모리 수치는 당시 기록한 값이며, 양자화 방식, 실행 도구, 문맥 길이 등이 명시되어 있지 않아 모든 환경의 최소 요구 사양으로 보기는 어렵습니다.

### 테스트 환경

- CPU: 80-core
- RAM: 320GB
- GPU: T4 x4
- Python: v3.10

### LLaMA 7B, Alpaca 7B

당시 기록한 용량: 30GB, GPU Memory: 4GB (CPU 메모리를 이용하는 실행 방식도 있음)

- 성능을 크게 잡아먹지 않아서 간편하게 사용하기 용이
- 프로덕트에 도입하기에는 부족
- 영어 중심으로 활용하는 데 적합
- 대화 정도는 괜찮지만 코드 생성이나 블로그 글 작성 등의 생산 기능이 부족
- 당시 살펴본 구현은 REST API로 사용하려면 별도 서버 코드가 필요

### Vicuna 13B

당시 기록한 용량: 40GB, GPU Memory: 28GB 또는 CPU Memory 60GB

- LLaMA, Alpaca에 비해 훨씬 나음
- 한국어를 어느 정도 알아듣는다
- 대화도 어느 정도 통하고 생산성 기능도 괜찮음

![2023-04-08-image4](2023-04-08-image4.png)

### GPT-3.5-turbo

- [API 제공](https://platform.openai.com/docs/introduction)
- 가격: 1K Token당 $0.002 (2023년 4월 당시 가격)
- 말이 필요 없죠
- API를 제공하기 때문에 사용성 면에선 최상
- 프로덕트에 쓰려면 이전 대화 기억 같은 추가 작업이 필요해요
