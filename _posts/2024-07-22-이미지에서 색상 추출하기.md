## 🔥 첫 번째 도전: 성능 최적화

가장 먼저 부딪힌 문제는 **성능**이었습니다.

처음에는 모든 픽셀을 분석했는데, 큰 이미지를 처리할 때마다 성능이 급격히 떨어지는 문제가 있었습니다.

### 문제 상황
```javascript
// 모든 픽셀 분석 (비효율적)
for (let y = 0; y < height; y++) {
  for (let x = 0; x < width; x++) {
    // 모든 픽셀 처리...
  }
}
// 4K 이미지 (3840 × 2160) = 8,294,400 픽셀!
```
{: .nolineno }

### ✅ 해결책: 픽셀 샘플링

모든 픽셀을 분석하는 대신 **일정 간격으로 픽셀을 샘플링**하는 방식을 도입했습니다.
```javascript
// 샘플링 적용 (효율적)
const samplingRate = 10; // 10픽셀마다 샘플링
for (let y = 0; y < height; y += samplingRate) {
  for (let x = 0; x < width; x += samplingRate) {
    // 샘플링된 픽셀만 처리
  }
}
// 4K 이미지도 82,944 픽셀만 처리!
```
{: .nolineno }

| 접근법 | 처리 픽셀 수 | 성능 개선 |
|:---|---:|---:|
| **전체 분석** | 8,294,400 | - |
| **샘플링 (10)** | 82,944 | 약 100배 향상 |
| **샘플링 (20)** | 20,736 | 약 400배 향상 |

> **⚖️ 트레이드오프**  
> 사용자가 샘플링 비율을 조절할 수 있게 하여 성능과 정확도의 균형을 맞출 수 있도록 했습니다.

### ✅ 해결책: 어댑터 패턴

환경별 어댑터를 별도로 만들어 차이를 추상화했습니다.
```typescript
// 공통 인터페이스
interface ImageAdapter {
  loadImage(source: string | Buffer): Promise<ImageData>;
  getPixelData(image: ImageData): Uint8ClampedArray;
}

// 브라우저용 어댑터
class BrowserAdapter implements ImageAdapter {
  async loadImage(source: string): Promise<ImageData> {
    const img = new Image();
    img.src = source;
    await img.decode();
    
    const canvas = document.createElement('canvas');
    const ctx = canvas.getContext('2d')!;
    canvas.width = img.width;
    canvas.height = img.height;
    ctx.drawImage(img, 0, 0);
    
    return ctx.getImageData(0, 0, img.width, img.height);
  }
}

// Node.js용 어댑터
class NodeAdapter implements ImageAdapter {
  async loadImage(source: string | Buffer): Promise<ImageData> {
    const sharp = require('sharp');
    const { data, info } = await sharp(source)
      .raw()
      .toBuffer({ resolveWithObject: true });
    
    return {
      data: new Uint8ClampedArray(data),
      width: info.width,
      height: info.height,
    };
  }
}
```

## 🎯 세 번째 도전: 색상 정확도

**K-means 알고리즘**을 사용해 색상을 군집화했는데, 때때로 결과가 일관성이 없었습니다.

### K-means 알고리즘이란?

> K-means는 데이터를 K개의 그룹으로 나누는 클러스터링 알고리즘입니다.  
> 색상 추출에서는 RGB 값을 3차원 공간의 점으로 간주하여 유사한 색상끼리 묶습니다.
{: .prompt-info }

### 문제점
```text
같은 이미지, 다른 결과?
실행 1: #FF5733, #33FF57, #5733FF
실행 2: #FF6844, #44FF68, #6844FF
실행 3: #FF4922, #22FF49, #4922FF
```
{: .nolineno }

초기 중심점(centroid)이 무작위로 선택되어 결과가 매번 달라지는 문제가 발생했습니다.

### ✅ 해결책: 다중 실행과 결과 안정화

#### 1. 알고리즘 여러 번 실행
```typescript
function extractColors(imageData: ImageData, k: number, runs: number = 10) {
  const results = [];
  
  for (let i = 0; i < runs; i++) {
    const colors = kMeans(imageData, k);
    results.push(colors);
  }
  
  // 가장 낮은 분산을 가진 결과 선택
```

#### 2. CIEDE2000 알고리즘 적용

사람의 시각과 유사하게 색상 차이를 계산하는 **CIEDE2000** 알고리즘을 적용했습니다.
```typescript
function colorDistance(color1: RGB, color2: RGB): number {
  // CIEDE2000 알고리즘 구현
  const lab1 = rgbToLab(color1);
  const lab2 = rgbToLab(color2);
  
  return ciede2000(lab1, lab2);
}

// 유사한 색상 병합
function mergeSimilarColors(colors: RGB[], threshold: number = 5) {
  const merged = [];
  
  for (const color of colors) {
    const similar = merged.find(c => colorDistance(c, color) < threshold);
    
    if (similar) {
      // 평균값으로 병합
      Object.assign(similar, averageColors([similar, color]));
    } else {
      merged.push(color);
    }
  }
  
  return merged;
}
```

| 방법 | 장점 | 단점 |
|:---|:---|:---|
| **단일 실행** | 빠름 | 결과 불안정 |
| **다중 실행** | 안정적 결과 | 처리 시간 증가 |
| **CIEDE2000** | 시각적으로 정확 | 계산 복잡도 증가 |
