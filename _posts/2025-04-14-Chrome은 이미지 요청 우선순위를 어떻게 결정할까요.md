## 🚀 들어가며

이 글에서는 Chrome 브라우저가 이미지 리소스에 대한 요청 우선순위를 어떻게 결정하는지 자세히 살펴보겠습니다.

우선순위 결정 방식의 원리를 이해하고, 중요한 이미지를 더 빠르게 로드하기 위해 사용할 수 있는 최적화 기법들을 소개합니다.

---

## 📉 이미지 요청은 기본적으로 '낮음(Low)' 우선순위를 가집니다

기본적으로 이미지 요청은 **낮음(Low)** 우선순위를 갖습니다.

### 렌더링 차단 리소스 우선 처리

브라우저는 이미지를 로드하기 전에 다음 리소스들의 로드를 먼저 처리합니다:

| 우선 처리 대상 | 설명 |
|:---|:---|
| 🚫 **렌더링 차단 리소스** | HTML, CSS, 동기 JavaScript |
| ⛓️ **핵심 요청 체인** | 페이지 렌더링에 필수적인 리소스 |

아래 요청 워터폴(waterfall) 예시를 보면 여러 이미지 요청이 '낮음(Low)' 우선순위로 처리되는 것을 확인할 수 있습니다.

![이미지 기본 우선순위](2025-04-14-image1.png)
_여러 이미지가 Low 우선순위로 처리되는 모습_

> **⏱️ 대기 시간 분석**  
> 회색 막대는 대기 시간을 나타내며, 이 예시에서는 700ms가 넘는 경우가 많습니다. Chrome은 페이지 렌더링이 시작될 때까지 이러한 낮은 우선순위 리소스의 요청을 시작조차 하지 않습니다.
{: .prompt-warning }

### 2단계 로딩 전략

가장 중요한 페이지 리소스가 로드된 후에야 Chrome은 **낮음(Low)** 우선순위의 이미지를 로드하기 시작합니다.
```text
로딩 단계:

1단계: 엄격 모드 (Tight Mode)
├── HTML 파싱
├── CSS 로드 및 파싱
├── 렌더링 차단 JavaScript 실행
└── 초기 렌더링 준비

2단계: 완화 모드
├── Low 우선순위 이미지 로드 시작
└── 기타 지연 가능한 리소스 로드
```
{: .nolineno }

![리소스 로딩 타임라인](2025-04-14-image2.png)
_핵심 리소스 로드 후 이미지 로딩 시작_

> **🔍 엄격 모드 (Tight Mode)**  
> Chrome은 리소스를 두 단계로 로드합니다. 초기 단계인 '엄격 모드'에서는 브라우저가 낮은 우선순위 요청에 자원을 사용하지 않으려고 합니다.
{: .prompt-info }

## ⬆️ Chrome 117 버전부터 처음 5개의 '큰 이미지' 우선순위가 향상되었습니다

Chrome 117 버전부터 Google은 처음 로드되는 5개의 **큰 이미지**의 우선순위를 **낮음(Low)** 에서 **중간(Medium)** 으로 상향 조정했습니다.

### 변경 사항 요약

| 항목 | 이전 (< Chrome 117) | 현재 (≥ Chrome 117) |
|:---|:---:|:---:|
| 처음 5개 큰 이미지 | Low | Medium |
| 6번째 이후 큰 이미지 | Low | Low |
| 일반 이미지 | Low | Low |

이는 주요 이미지가 더 빠르게 로드되도록 돕기 위한 변경입니다.

![중간 우선순위 이미지](2025-04-14-image3.png)
_5개 이미지가 Medium 우선순위 할당받은 모습_

> **📊 LCP 개선 효과**  
> 이 접근 방식은 효율적인 리소스 로딩을 유지하면서도 주요 이미지의 우선순위를 높여 최대 콘텐츠풀 페인트(Largest Contentful Paint, LCP) 점수를 개선하는 데 도움을 줍니다.
{: .prompt-tip }

## 📏 '큰 이미지'란 무엇일까요?

면적이 **10,000 픽셀² 이상**인 이미지는 **큰 이미지**로 간주되어 **중간(Medium)** 우선순위로 상향 조정될 수 있습니다.

### 크기 계산 방식
```html
<!-- 큰 이미지로 간주됨 (Medium 우선순위) -->
<img src="hero.jpg">
<!-- width, height 미지정 → 기본값으로 큰 이미지 간주 -->

<img src="banner.jpg" width="200" height="100">
<!-- 200 × 100 = 20,000 픽셀² → 큰 이미지 -->

<!-- 큰 이미지로 간주되지 않음 (Low 우선순위 유지) -->
<img src="icon.jpg" width="10" height="10">
<!-- 10 × 10 = 100 픽셀² → 작은 이미지 -->
```
{: .nolineno }

#### 예시 1: 크기 미지정

![크기 미지정 이미지](2025-04-14-image4.png)
_width/height 미지정 → 기본적으로 큰 이미지로 간주_

#### 예시 2: 작은 크기 지정

![작은 크기 이미지](2025-04-14-image5.png)
_10×10 픽셀로 지정 → Low 우선순위 유지_

| 이미지 크기 | 면적 | 우선순위 |
|:---|---:|:---:|
| `width/height` 미지정 | N/A | Medium (처음 5개) |
| 200 × 100 | 20,000 픽셀² | Medium (처음 5개) |
| 100 × 100 | 10,000 픽셀² | Medium (처음 5개) |
| 99 × 100 | 9,900 픽셀² | Low |
| 10 × 10 | 100 픽셀² | Low |

> **⚠️ 중요 포인트**  
> `width`와 `height` 속성이 지정되지 않은 경우, Chrome은 해당 이미지를 기본적으로 '큰 이미지'로 간주합니다.
{: .prompt-info }

## 👁️ 이미지가 뷰포트(Viewport)에 진입하면 **높음(High)** 우선순위로 변경됩니다

모든 이미지는 기본적으로 **낮음(Low)** 우선순위를 갖지만, 이미지가 화면에 보이는 영역, 즉 **뷰포트(viewport)** 에 들어오면 그 우선순위는 **높음(High)** 으로 변경됩니다.

### 우선순위 변경 타이밍
```text
페이지 로드 시퀀스:

1. 초기 로드
   └── 이미지 우선순위: Low

2. FCP (First Contentful Paint)
   └── 문서 파싱 시작

3. 뷰포트 진입 감지
   └── 이미지 우선순위: Low → High

4. 이미지 다운로드 시작
   └── 높은 우선순위로 처리
```
{: .nolineno }

이 변경은 일반적으로 **최초 콘텐츠풀 페인트(First Contentful Paint, FCP)** 이후에 발생합니다.

### LCP 이미지 문제

이는 LCP 이미지에 문제를 일으킬 수 있습니다.

| 단계 | 우선순위 | 문제점 |
|:---|:---:|:---|
| 초기 로드 | Low | 우선순위 낮음 |
| 뷰포트 진입 감지 | High | 이미 늦음 |
| 실제 로드 시작 | High | LCP 지연 발생 |

대부분의 경우 LCP 이미지는 페이지 로드 중에 우선순위가 **낮음(Low)** 에서 **높음(High)** 으로 변경되는 것을 관찰하게 됩니다.

![우선순위 변경](2025-04-14-image6.png)
_LCP 이미지의 우선순위가 Low에서 High로 변경_

> **⏰ 타이밍 문제**  
> 이 변경은 브라우저가 문서 파싱을 시작하고 해당 이미지가 뷰포트에 있음을 인지한 후에 발생하며, 이는 이미지가 초기에 계획된 것보다 더 빨리 렌더링되도록 우선순위를 높이는 효과를 줍니다. 하지만 이 시점은 이미 LCP 측정에 영향을 줄 수 있을 만큼 늦을 수 있습니다.
{: .prompt-warning }

## 🎯 `fetchpriority` 속성으로 우선순위를 직접 제어할 수 있습니다

개발자는 `fetchpriority` 속성을 사용하여 이미지 로딩 우선순위를 직접 제어할 수 있습니다.

### 사용 방법
```html
<!-- LCP 이미지: 높은 우선순위 명시 -->
<img 
  src="hero-image.jpg" 
  alt="Hero Image"
  fetchpriority="high"
>

<!-- 중요하지 않은 큰 이미지: 낮은 우선순위 유지 -->
<img 
  src="decorative-image.jpg" 
  alt="Decorative"
  fetchpriority="low"
  width="500" 
  height="300"
>

<!-- 기본 우선순위 -->
<img 
  src="normal-image.jpg" 
  alt="Normal"
>
```
{: .nolineno }

### fetchpriority="high"

LCP 이미지에 이 속성을 설정하면 브라우저가 가능한 한 빨리 해당 이미지를 로드하도록 우선순위를 부여합니다.

![fetchpriority high](2025-04-14-image7.png)
_fetchpriority="high"로 즉시 높은 우선순위 할당_

| 효과 | 설명 |
|:---|:---|
| ⚡ **즉시 높은 우선순위** | 뷰포트 진입 감지 대기 불필요 |
| 📈 **LCP 개선** | 렌더 지연 감소 |
| 🎯 **명확한 의도** | 개발자의 의도 명시적 표현 |

> **✅ LCP 최적화**  
> 이는 LCP 렌더 지연(LCP Render Delay)과 같은 근본적인 문제가 없다면 LCP 점수를 크게 향상시킬 수 있습니다.
{: .prompt-tip }

### fetchpriority="low"

뷰포트 밖에 있는 큰 이미지에 이 속성을 설정하여 의도적으로 '낮음(Low)' 우선순위를 유지시킬 수 있습니다.
```html
<!-- 큰 이미지지만 중요하지 않음 -->
<img 
  src="footer-banner.jpg" 
  alt="Footer Banner"
  width="1200" 
  height="400"
  fetchpriority="low"
>
<!-- 기본적으로 Medium이 되지만, Low로 유지 -->
```
{: .nolineno }

![fetchpriority low](2025-04-14-image8.png)
_fetchpriority="low"로 5개 큰 이미지 중 하나를 Low로 유지_

> **🎛️ 리소스 관리**  
> 이는 중요도가 낮은 이미지 때문에 중요한 리소스 로딩이 지연되는 것을 방지하는 데 도움이 됩니다.
{: .prompt-info }

## 🔗 이미지 프리로딩(Preloading) 요청의 우선순위

이미지 로딩을 관리하는 또 다른 방법은 **프리로딩(`<link rel="preload">`)** 을 사용하는 것입니다.

### 프리로딩 사용 사례
```html
<head>
  <!-- CSS 배경 이미지 프리로드 -->
  <link 
    rel="preload" 
    as="image" 
    href="hero-bg.jpg"
  >
  
  <!-- JavaScript로 로드되는 이미지 프리로드 -->
  <link 
    rel="preload" 
    as="image" 
    href="dynamic-image.jpg"
  >
  
  <!-- fetchpriority와 함께 사용 -->
  <link 
    rel="preload" 
    as="image" 
    href="critical-image.jpg"
    fetchpriority="high"
  >
</head>
```
{: .nolineno }

| 프리로드 대상 | 사유 |
|:---|:---|
| CSS 배경 이미지 | HTML에서 직접 참조 안 됨 |
| JS 동적 이미지 | 런타임에 결정됨 |
| 폰트 파일 | 늦게 발견될 수 있음 |

### 우선순위 주의사항

프리로드된 리소스의 우선순위는 해당 리소스 유형의 **기본 우선순위와 동일**합니다.
```text
프리로드 우선순위:

<link rel="preload" as="image">
└── 기본 우선순위: Low

<link rel="preload" as="script">
└── 기본 우선순위: High

<link rel="preload" as="style">
└── 기본 우선순위: Highest
```
{: .nolineno }

따라서 이미지를 프리로드해도 기본적으로는 '낮음(Low)' 우선순위를 유지합니다.

![프리로드 우선순위](2025-04-14-image9.png)
_프리로드된 이미지도 Low 우선순위 유지_

> **⚠️ 프리로드 한계**  
> 프리로드는 리소스를 **조기에 발견**하게 하지만, **우선순위를 자동으로 높이지는 않습니다**. 높은 우선순위가 필요하다면 `fetchpriority="high"`를 함께 사용해야 합니다.
{: .prompt-warning }

### 프리로드 + fetchpriority 조합
```html
<!-- 최적의 조합: 조기 발견 + 높은 우선순위 -->
<link 
  rel="preload" 
  as="image" 
  href="lcp-image.jpg"
  fetchpriority="high"
>
```
{: .nolineno }

## 📊 우선순위 전략 요약

다양한 이미지 최적화 기법들을 정리하면 다음과 같습니다:

| 기법 | 사용 시기 | 우선순위 효과 |
|:---|:---|:---|
| **기본 동작** | 일반 이미지 | Low |
| **큰 이미지 (처음 5개)** | 자동 (Chrome 117+) | Medium |
| **뷰포트 진입** | 이미지가 보일 때 | High |
| **fetchpriority="high"** | LCP 이미지 | High (즉시) |
| **fetchpriority="low"** | 중요하지 않은 이미지 | Low (강제) |
| **preload** | 늦게 발견되는 이미지 | 조기 발견 (우선순위 동일) |
| **preload + fetchpriority** | 중요한 늦은 이미지 | 조기 발견 + High |

## 💡 베스트 프랙티스

### LCP 이미지 최적화
```html
<!-- 1. LCP 이미지에 fetchpriority="high" 사용 -->
<img 
  src="hero.jpg" 
  alt="Hero Image"
  fetchpriority="high"
  width="1200" 
  height="600"
>

<!-- 2. CSS 배경 이미지가 LCP라면 프리로드 -->
<head>
  <link 
    rel="preload" 
    as="image" 
    href="hero-bg.jpg"
    fetchpriority="high"
  >
</head>
```
{: .nolineno }

### 큰 이미지 관리
```html
<!-- 중요하지 않은 큰 이미지 우선순위 낮추기 -->
<img 
  src="decorative-large.jpg" 
  alt="Decoration"
  width="800" 
  height="400"
  fetchpriority="low"
  loading="lazy"
>
```
{: .nolineno }

### 반응형 이미지
```html
<!-- srcset과 fetchpriority 조합 -->
<img 
  srcset="
    hero-400.jpg 400w,
    hero-800.jpg 800w,
    hero-1200.jpg 1200w
  "
  sizes="(max-width: 600px) 400px, 
         (max-width: 1200px) 800px, 
         1200px"
  src="hero-1200.jpg"
  alt="Hero"
  fetchpriority="high"
>
```
{: .nolineno }

## 🎓 결론

Chrome의 이미지 우선순위 시스템을 이해하고 활용하면 웹 성능을 크게 개선할 수 있습니다.

### 핵심 요점

| 원칙 | 실행 방법 |
|:---|:---|
| 🎯 **LCP 최적화** | `fetchpriority="high"` 사용 |
| 📉 **불필요한 경쟁 방지** | `fetchpriority="low"` 활용 |
| 🔍 **조기 발견** | `<link rel="preload">` 사용 |
| 📏 **적절한 크기 지정** | `width`, `height` 속성 명시 |
| ⏳ **지연 로딩** | `loading="lazy"` 뷰포트 밖 이미지에 적용 |

> **🚀 성능 개선 팁**  
> 가장 중요한 이미지(LCP)에 `fetchpriority="high"`를 적용하고, 덜 중요한 큰 이미지에는 `fetchpriority="low"`를 사용하여 리소스를 효율적으로 관리하세요.
{: .prompt-tip }
